# Fiscal CSV consumer guide

This file orients a downstream reader (human or LLM) to the CSV outputs
produced by the parsers in `extractors/fiscal/`. The CSVs live in
`out_fiscal/` (gitignored; regenerated by running the `extract_*.py`
scripts plus `build_sources.py`). For schema docs see
`extractors/fiscal/schemas/`; for known gaps see
`extractors/fiscal/TODO.md`.

## What the data is

OSPI publishes SAFS / apportionment fiscal reports per Washington school
district / ESD / college / state agency / state institution per school
year. The scraper at
`docs/contentscripts/scrappers/ospi-funding-reports.js` pulls every
document into `data/fiscal/`, which `extractors/fiscal/reorg.py` then
reorganizes into a `report_type / year / org_type / org / [member] /` tree
(see the top of `reorg.py` for the layout). The parsers turn those source
files into long-form fact tables plus dimension tables, mirroring the
STARS pattern in `extractors/stars/`.

## Common keys used to join

Every fact table carries the `SCHOOL_YEAR_DISTRICT_FIELDS` columns
(reused from `extractors/safs/schemas/common.py`):

- `school_year` (string, e.g. `2024-2025`)
- `class_of` (int, end year of `school_year`)
- `ccddd` (int, OSPI county-and-district code; `0` for state-summary aggregates)
- `county` (currently blank; populate via `extractors/safs/schemas/domains.py:d_ccddd`)
- `district` (district name as printed; **free text, not a canonical FK**)

So fact rows join to the SAFS budget/actuals tables on `(class_of, ccddd)`
and to STARS facts on the same key.

Every fact table also carries:

- `_source_id` (int) -- FK to `d_fiscal_source.source_id`. Replaces the
  long source path string.
- `_source_table` (string) -- always equals the table name; useful when
  unioning multiple tables.

## Schema landmarks

### `fiscal_state_institutions`

Long-form per Form 1191SI line item. **The form's row layout drifts
across years**, so the parser captures items by their printed section
letter / item path verbatim rather than mapping to a canonical layout.
See `schemas/state_institutions.py` for the full schema docstring.

Highlights:

- Logical key includes `institution_name` because multiple institutions
  share a `(ccddd, revenue_account)` pair (institutions are served by a
  district; the revenue account is an OSPI category, not an institution).
- `section_seq` distinguishes the two "K" sections (page-1 Total
  Allocation vs. page-2 Year-End Adjustment).
- `allocation_status` cycles through `Initial` / `Revised` / `Actual` /
  `Final` depending on report vintage.
- The State Summary aggregate uses `ccddd=0` and `institution_name='State Summary'`.

### `fiscal_food_service`

Long-form for Report 1800SUM Food Service Program Summary. Form is
stable across years; the only drift is a "New Balances" subheader added
in 2018-19. Five sections:

| section | items | notes |
|---|---|---|
| `revenues` | paid_lunches, state_payment, federal_payment, federal_commodities, other_payments, total_revenues | single value per row |
| `expenditures` | salaries_benefits, supplies, purchased_services, food_supplies, food_purchased_services, travel_other, capital_outlay, total_direct | `subkey` carries `direct` / `object1_alloc` / `net`. `is_indirect_calc=True` on net-column rows that the form flagged with `*`. |
| `indirect` | unrestricted_indirect_rate (%), applied_indirect | rate stored as the printed number (`18.16` means 18.16%, not 0.1816) |
| `summary` | total_expenditures, excess_deficit | excess_deficit may be negative |
| `carryforward` | annual_balance (one per data year, via `subkey`), net_balance_carryforward, three_months_avg_expenditures | most reports show 5 years of `annual_balance`; 2014-15 reports show 6 |

**Coverage gap**: only 2013-14 through 2018-19 have data; OSPI stopped
publishing this report after 2018-19.

### `fiscal_f195_overview`

5-fund matrix from page 1 of F-195 Budget Overview (the remaining 40
pages of the PDF duplicate the F-195 Budget full document and are
deferred).

| column | meaning |
|---|---|
| `section` | `a_budget_summary` (7 items) or `b_excess_levies` (3 items) |
| `item_code` | **positional** code -- stable across years even when label text wraps differently. See `schemas/f195_overview.py` for the canonical list. |
| `fund` | `general`, `asb`, `debt_service`, `capital_projects`, or `transportation_vehicle` (column order on the form) |
| `value` | NULL when the form printed `XXXX` / `XXXXX` (item doesn't apply to that fund -- e.g. ASB has no excess levies) |

### `fiscal_f195_four_year`

Multi-page F-195F Four-year Budget Summary Plan. One row per (item,
data year column) -- each value-bearing line on the form emits 4 long-
form rows (current + 3 forecasts).

| column | meaning |
|---|---|
| `fund` | `general`, `asb`, `debt_service`, `capital_projects`, `transportation_vehicle`, or `enrollment_staff` (the pre-fund table on page 1) |
| `section` | `revenues` / `expenditures` / `beginning_balance` / `ending_balance` / `summary` (totals -- section-letter rows like 'A. TOTAL REVENUES') / `enrollment` / `staff` |
| `item_code` | OSPI code prefix (`1000`, `6000`, `G.L.840`, `A`, `H`), or a slug of the label when no prefix is recognized (e.g. `matured_bond_expenditures`) |
| `data_year_offset` | `0` = current year column, `1`/`2`/`3` = forecast columns |
| `data_school_year` | The year the column reports on, e.g. `2024-2025` |

### `fiscal_f195_budget`

Per-line-item capture of the SUMMARY OF X FUND BUDGET sub-reports
embedded in OSPI Form F-195 Budget and F-195 Budget Overview PDFs.
One occurrence per fund per file -- the 5 funds always print in the
same order (General, ASB, Debt Service, Capital Projects, Transportation
Vehicle). Each value-bearing source line emits 3 rows (one per data
column: Actual prior-prior year, Budget prior year, Budget current
year).

The schema is keyed on `sub_report` so future additions (per-program
expenditure, per-object expenditure, etc.) can populate the same table
without migration. Phase 1 emits only `sub_report = 'fund_summary'`.

| column | meaning |
|---|---|
| `sub_report` | `fund_summary` (only value emitted today; see TODO for planned future values: `fund_revenue_detail`, `expenditure_by_program`, `expenditure_by_object_summary`, `expenditure_by_activity_summary`, `enrollment_and_staff_counts`, `financial_summary`). |
| `fund` | `general`, `asb`, `debt_service`, `capital_projects`, or `transportation_vehicle`. |
| `section` | `revenues` / `expenditures` / `beginning_fund_balance` / `ending_fund_balance` / `summary` (totals -- section-letter rows like 'A. TOTAL REVENUES'). |
| `item_code` | OSPI revenue/expenditure account code (`1000`, `6000`, `90`), G.L. code (`G.L.810`), section letter (`A`, `B`, `H` for totals), or a slug of the label when no prefix is recognized (e.g. Debt Service Fund's `matured_bond_expenditures`). |
| `data_year_offset` | `-2` (prior actual) / `-1` (prior budget) / `0` (current budget). |
| `data_school_year` | The year the column reports on, e.g. `2024-2025`. |
| `column_kind` | `actual` (offset `-2`) or `budget` (offsets `-1` and `0`). |
| `item_label` | Line item label as printed (whitespace normalized). Multi-line labels are joined. |
| `value` | Parsed decimal. NULL when the form printed `XXXX` / `XXXXX` (column doesn't apply to that line item -- e.g. PRIOR YEAR CORRECTIONS prints `XXXXX` for all 3 years on most filings). |

Both F-195 Budget and F-195 Budget Overview produce **identical row
sets** for a (school_year, ccddd) pair (the SUMMARY pages are the
same in both source kinds). The dedup-by-logical-key inside the parser
collapses re-occurrences; downstream callers can pick rows by
`_source_id` to track which physical file a row came from.

**Coverage**: 2013-14 through 2025-26, district-level only. Same set
of districts as the rest of the `fiscal/<year>/` corpus (~310/year).

### `fiscal_f196_summary`

7-fund x 7-item matrix from page 2 of every `F-196 All Pages.pdf`. The
SUMMARY block is the headline cross-fund rollup: revenues, expenditures,
other financing uses, beginning/ending fund balance, prior-year
corrections. Complements `fiscal_f195_overview` (budget vs actuals).

| column | meaning |
|---|---|
| `item_code` | positional canonical name (`total_revenues_and_other_financing_sources`, `total_expenditures`, `other_financing_uses`, `excess_of_revenues_over_expenditures`, `beginning_total_fund_balance`, `corrections_or_restatements`, `ending_total_fund_balance`). The printed label drifts -- e.g. `Prior Year(s) Corrections or Restatements` -> `Accounting Changes and Error Corrections` in later vintages -- but `item_code` is stable. |
| `fund` | `general`, `asb`, `debt_service`, `capital_projects`, `transportation_vehicle`, `permanent`, or `total` (the `total` column is the printed cross-fund sum -- useful as a cross-check) |
| `value` | Parsed decimal. **NULL when the form left the cell blank** -- older vintages (through ~2020-21) leave non-applicable cells truly blank (most commonly ASB / Permanent / Transportation Vehicle on `other_financing_uses`). 2021-22+ vintages fill those with explicit 0.00. The cross-fund invariant `total = sum(general..permanent over non-NULL values)` holds on every file. |

**Coverage**: 2013-14 through 2024-25 (3,724 files, district-level
only). Sourced from `F-196 All Pages.pdf` under `data/fiscal/fiscal/`.
Note that this is "all pages" of the audited statement filing, but the
audit status varies by vintage:

- 2013-14, 2014-15: the All Pages doc is the mid-December unaudited
  filing. OSPI also publishes a separate `F-196 Unaudited.pdf` under
  `apportionment/` for these two years; the SUMMARY block is the same
  content captured by `fiscal_f196_unaudited_summary` (see overlap note
  below).
- 2015-16 through 2020-21: SUMMARY data lives only in `F-196 All Pages.pdf`.
  This range is the unique-coverage contribution of this parser -- the
  previously-published `fiscal_f196_summary` started at 2021-22.
- 2021-22 through 2024-25: OSPI introduced the split-out standalone
  `F-196 Summary.pdf` doc (audited final). Its SUMMARY block is byte-
  identical to page 2 of the same year's All Pages doc; the All Pages
  parser populates `fiscal_f196_summary` and the standalone-Summary
  parser was retired.

**Overlap with `fiscal_f196_unaudited_summary`** (2013-14, 2014-15):
both tables now hold rows for those two years from different physical
source PDFs (apportionment-corpus Unaudited filing vs. fiscal-corpus
All Pages filing). The two filings carry the same SUMMARY content;
consumers wanting one continuous series can `UNION ALL` on
`(school_year, ccddd, item_code, fund)` and dedupe by source preference,
or just query `fiscal_f196_summary` alone (it covers the full range).

### `fiscal_apportionment_monthly`

Per-month state payment to each district / college / state agency,
broken down by OSPI revenue account. The headline number per row is
`allotment_for_month` -- the actual dollars the state paid out that
month. The other five columns (`annual_allotment`, `adjustment_allotment`,
`percent_due`, `allot_due`, `paid_previously`) carry the year-to-date
allotment math.

| column | meaning |
|---|---|
| `org_type` | `district`, `college`, `state_agency`, or `esd` (the 9 ESDs' own apportionments). For `esd` rows, `ccddd` is the ESD's own code (e.g. 17801 for Puget Sound ESD 121), parsed from the PDF body -- not the path-derived member-district code. |
| `month` | September through August. Apportionment year runs Sept-Aug (school fiscal year). |
| `month_seq` | 1-12 within the school year (Sept=1, Aug=12). Useful for chronological sort. |
| `revenue_account` | OSPI revenue account code (`3100` = Regular Apportionment, `4121` = Special Education, `6113` = ESSER III, etc.) plus two sentinels: `TOTALS` (sum row at the bottom of the table) and `GENERAL_FUND_ONLY_TOTAL` (net summary line below). |
| `revenue_description` | Description as printed -- **part of the logical key** because older years (2013-14 / 2014-15) print multiple sub-program rows under the same account code (e.g. `3100 FED FOREST`, `3100 FIRE`, `3100 REGULAR APPORTIONMENT` all carry account `3100`). |
| `annual_allotment` | Column A: total annual allotment. |
| `adjustment_allotment` | Column B: previous/current year adjustment. |
| `percent_due` | Column C: this month's share as a decimal (`0.0900` for the standard 9% Sept-May share). NULL on Totals rows. |
| `allot_due` | Column D: dollars due this month (= C*A + B). |
| `paid_previously` | Column E: dollars previously paid YTD. |
| `allotment_for_month` | Column F: dollars actually paid this month. |

**Coverage caveat**: ~2,900 (5%) of the apparently-monthly-Apportionment
files OSPI publishes are actually **cover-memo PDFs** instead of the
Statement of Apportionment table (same filename, different content).
These produce 0 rows -- they're not parse errors.

### `fiscal_f780_levy`

Per-district per-levy-year report of the levy authority cap (Schedule
I), Maximum LEA (Schedule II), and LEA Payable (Schedule III), plus a
SUMMARY block. Two flavors per (district, levy_year):

- `Initial` -- published in October before the levy year, ahead of
  voter approval and certification. Uses preliminary AV.
- `Final` -- published in April of the levy year, after certification.
  Reflects the certified levy.

| column | meaning |
|---|---|
| `levy_year` | Calendar year of levy collection (e.g. 2025). Distinct from `school_year` (an Initial F-780 for levy year 2025 is published Oct 2024, in school year 2024-2025). |
| `status` | `Initial` or `Final`. |
| `section` | `summary` / `schedule_i` (Estimated Levy Revenue) / `schedule_ii` (Maximum LEA) / `schedule_iii` (LEA Payable). |
| `item_code` | Letter (A, B, C, ...) for top-level items; slug-derived for the 2 sub-items under Schedule I.A. |
| `value` | Decimal -- dollar amounts, enrollment counts, rates, and percentages all share this column; consumers use `item_code` / `item_label` to interpret units. Parenthesized negatives (e.g. Schedule III.B rollback) parse to negative decimals. |

### `fiscal_1251_enrollment`

Per-district per-grade per-month enrollment from P-223 monthly counts, in
two flavors (FTE = Report 1251; headcount = Report 1251H). One row per
(section, grade, month) cell on the form.

| column | meaning |
|---|---|
| `report_kind` | `fte` or `headcount`. |
| `section` | Canonical section identifier slugged from the title (`total_k_12_basic_education_enrollment`, `total_ale_enrollment`, `running_start`, `open_doors`, `tbip`, `transition_to_kindergarten`, ...). Section availability differs across years and between FTE/headcount. |
| `grade` | Grade label as slug (`kindergarten`, `first`, ..., `twelfth`, `totals`, `grades_1_3`, `grade_4`, ...). Older form variants print multiple `TOTALS` rows within one section (a grand total plus sub-group totals); the 2nd/3rd get `totals_2` / `totals_3`. |
| `month` | All-caps column label as printed: `SEPTEMBER`-`JUNE` for most sections, with `JULY`/`AUGUST` added on sections that run year-round (Running Start, Open Doors, Transition To Kindergarten). `AVERAGE` is the trailing summary column on every row. |
| `value` | Parsed number. FTE values are decimals (e.g. `3,683.30`); headcount values are integers but stored as decimals for schema uniformity. |

**Scope caveat**: only district-level 1251 files are parsed. The
ESD-aggregate 1251 files (1,800-line reports under
`apportionment/<year>/esd/<esd>/<member>/`) are skipped -- they are
replicated under every member-district subdir and the format is a
multi-district aggregate that doesn't fit the per-district shape. ESD-
level enrollment will get its own dedup'd parser if needed.

### `fiscal_nonhigh_billing`

Per-district per-counterparty capture of Form F-483 Nonhigh Billing
Summary. F-483 is filed in two flavors and the form layout drifted at
the 2019-20 statutory rewrite (RCW 28A.545.030 added a "lesser of two
rates" provision and OSPI reissued the form):

- **F-483N** ("Non High District" POV): focal district is a K-8 / K-6
  nonhigh district sending students to one or more serving high
  districts. The focal `ccddd` is the sender.
- **F-483H** ("Serving High District" POV): focal district is a high
  school district receiving students from one or more sending nonhigh
  districts. The focal `ccddd` is the receiver.

The form drops from 4 columns (F-I) in the payable section pre-2019 to
5 columns (F-J) post-2019 -- the extra G column carries the "Lesser
Levy Rate" used in the post-rewrite formula. The levy block grew from
a single header-style A-E for the focal high district (pre-2019
F-483H) or per-counterparty A-E rows (pre-2019 F-483N) to TWO per-row
sub-tables (focal + counterparties) post-2019.

| column | meaning |
|---|---|
| `report_kind` | `f483n` (focal = nonhigh sender) or `f483h` (focal = high receiver). |
| `status` | `Final` for most files; `Initial` for all 2025-26 plus a handful of historical files. **Initial files omit column J** (November Payable, not yet computed). |
| `form_variant` | `pre_2019` (2013-14 through 2018-19) or `post_2019` (2019-20+). Captured for traceability -- consumers usually join on `item_code` instead. |
| `section` | `levy_per_aafte` (items A-E -- per-district levy / AAFTE calculation) \| `payable` (items F-J -- per-counterparty edge) \| `payable_total` (Total row at the bottom of the payable section). |
| `subject_role` | `high` or `nonhigh` -- the side of the equation that `subject_ccddd` is on. Empty for `payable_total` rows. |
| `subject_ccddd` | District whose data this row carries. For `levy_per_aafte` this is either the focal or a counterparty; for `payable` this is always the counterparty. 0 for `payable_total`. |
| `is_focal` | `True` if `subject_ccddd` equals the file's focal `ccddd`. |
| `item_code` | **Semantic** column identifier: `reported_resident_aafte`, `nonhigh_aafte`, `resident_aafte`, `payable_levy`, `levy_per_resident_aafte` (levy block); `sending_nonhigh_aafte`, `lesser_levy_rate_per_resident_aafte`, `total_school_year_payable`, `may_payable`, `november_payable` (payable block). The printed letter (A-J) is in `item_label`. **Letters were renumbered in the 2019 rewrite** (e.g. the levy in dollars moved from column A to column D) so the letter alone is NOT stable across years -- use `item_code`. |
| `item_label` | Printed column letter (A-J). |
| `value` | Decimal. Levies in dollars, AAFTE counts, rates, and per-row dollar payments share this column. Parenthesized negatives (`(232.40)` on Nonhigh AAFTE rows from a serving high's POV) parse to negative decimals. NULL for printed `-` and `$-` markers. |

**Coverage caveats**:
- 14 source PDFs (0.9%) are OSPI-internal spreadsheet errors (every
  data cell prints `#N/A`, district name renders as `0`). These
  produce 0 rows -- they're not parse failures.
- Pre-2019 F-483N files have NO `levy_per_aafte` row for the focal
  nonhigh district (the form doesn't print it). Join to
  `fiscal_f780_levy` on `(school_year, ccddd)` for the focal
  district's levy if needed.

### `fiscal_1191fg_grants`

Per-grant per-funding-line capture of OSPI Report 1191FG Grants
Administration. Each PDF is a recipient-keyed statement of every grant
the recipient has under active administration, with one or more
per-(`proj`, `pom`, `obj_sub`) funding-line rows per grant plus
rollups.

| column | meaning |
|---|---|
| `org_type` | `district` \| `esd` \| `college` \| `state_agency`. ESD files are deduped at the walker; CCDDD on those rows is the ESD's own (e.g. 34801 for ESD 113), not the inner member-district code embedded in the path. Most college / state_agency PDFs are header-only placeholders, but a handful (UW Seattle 17904, community colleges that run PEAB / Pesb programs) carry real grants. |
| `report_date_text` | As-of date printed at the top of the report (e.g. `08-30-19`). |
| `section` | `grant_detail` (one row per funding line within a grant) \| `grant_total` (per-grant rollup) \| `district_total` (recipient-level rollup, one per PDF). |
| `grant_seq` | Ordinal of the grant within the document (1-based). `0` on `district_total` rows. |
| `project_id` | Grant project identifier as printed (7-digit code, e.g. `0173935`). |
| `project_code` | Grant program short code (e.g. `PERKINS`, `TITLE1`, `ARPHMLESS`). |
| `project_description` | Description as printed (e.g. `Perkins Skill Ctrs`, `Title 1 PtA Basic`). Free text -- can be empty when the form's description column is blank. |
| `grant_period` | Grant fiscal-period code (e.g. `1819` = 2018-19, `2124` = multi-year ARP / ESSER grant). Empty when the form embeds the period in `project_description` (common in 2013-14). |
| `grant_status` | `OPEN` or `CLOSED`. |
| `revenue_account` | OSPI revenue account code from the grant's REV/EXPEND line (e.g. `6151`, `4158`). |
| `prior_expend` | Expenditures the recipient booked against this grant in prior periods, as of the report's as-of date. Replicated on every detail / grant_total row for the same grant. |
| `proj` | Per-detail funding-line code (e.g. `ZV19`, `TB18*`, `ZV18#`). Asterisk and hash suffixes are carryforward / adjustment markers preserved verbatim. Empty on `grant_total` / `district_total` rows. |
| `pom` | Per-detail POM code (e.g. `15014`, `BASIC`, `TARG3`). |
| `obj_sub` | Per-detail object/sub code (e.g. `NZ001`). |
| `funding` | Authorized funding for the line. On `grant_total` rows: sum across the grant's detail rows. On `district_total` rows: sum across grants. |
| `paid_adj` | Paid-to-date plus prior-period adjustments. |
| `curr_paymt` | Current period payment. |
| `balance` | Remaining = `funding - paid_adj - curr_paymt`. |

**Coverage caveats**:
- 13 source PDFs are corrupt (raw bytes, not real PDFs) in the OSPI scrape -- 1 in 2023-24, 12 in 2024-25, mostly small-district / charter-school files. These error out at the pdfplumber layer (`PdfminerException: No /Root object!`) and are not included in the CSV.
- 590 PDFs parse cleanly but emit 0 rows -- they are placeholder PDFs (header banner only). Concentrated in `college` / `state_agency` (most of those entities don't administer 1191FG grants) plus a handful of districts in the most recent vintage.
- 2024-25 is partial (138 PDFs with data vs ~330 in prior years) because the corpus was scraped mid-year; the snapshot reflects an intermediate run of the report.
- ESD-level files replicate under every member-district subdir of the ESD (~3,800 duplicate files per ESD per year). The walker emits each unique ESD file once.

### `fiscal_1220_sped`

Per-line-item capture of Report 1220 Special Education Allocations.
The form is dense -- 5 sections, ~30 letter-prefixed items, plus the
serving-district enrollment matrix that distributes the focal
district's enrollment across the high districts that serve its
students.

| column | meaning |
|---|---|
| `status` | `Final` (the end-of-year reconciled snapshot, ~Jan/Feb of the following calendar year) or a date string like `2019-08-31` (intermediate snapshots taken during the school year). Most files are `Final`; ~3% are mid-year snapshots. |
| `report_date_text` | Run date / time as printed at the top of the report (e.g. `24-Jan-20`). |
| `section` | `account_4121` (items A-M -- Special Education Excess Cost calculation) \| `serving_district_enrollment` (per-counterparty A-D enrollment matrix that derives the Account 4121 totals) \| `account_3121` (items N-X -- General Apportionment for SpEd) \| `summary` (cross-section totals + PLD breakdown) \| `account_4122` (Infants & Toddlers allocation). |
| `item_code` | Printed letter (A, B, ..., AA) for top-level items. Sub-items under J use the `J.1` / `J.2` / `J.3` form. Items without a letter prefix get a stable slug: `pld_portion_bea_rate` (the indented item under H), `total_allocation_spe21`, `pld_pct`, `pld_portion` (summary items). **Account 4122 items always use semantic slugs** (`age_0_2_allocation`, `transfer_acct_4122`, `total_acct_4122`) because the printed letters drifted between vintages (pre-2019: Y/Z/AA; 2019-20+: V/W/X). |
| `item_label` | Item label as printed (whitespace normalized). For wrapped items (F, G) the parent line label and continuation are joined with ` / `. |
| `subject_ccddd` | Serving high district CCDDD on `serving_district_enrollment` rows; 0 elsewhere. The serving-district matrix TOTAL row also uses `subject_ccddd = 0`. |
| `subject_name` | Serving high district name as printed (empty on non-serving-district rows). |
| `value` | Parsed numeric value. Dollar amounts, AAFTE counts, rates, and percentages all share this column. **Percentages are stored as the printed number** (`18.53` for 18.53%, not 0.1853). Parenthesized negatives (V "prior-year adjustment" can be negative) parse to negative decimals. NULL for the printed `-` zero placeholder. |
| `value_text` | Raw value text including any `$` or `%` suffix. |

**Invariants** that hold across the entire corpus (cross-check fields):
- `account_4121.M = account_4121.I + account_4121.J.3 + account_4121.K + account_4121.L`
- `summary.total_allocation_spe21 = account_4121.M + account_3121.U`

**Coverage caveats**:
- District-level files only. ESD-level files use a different form
  (Report 1220TR Transfer of Allocation) and are skipped; a parallel
  `fiscal_1220_sped_transfer` table is in TODO.md.
- Account 3121 items V, W, X (prior-year adjustments to 3121) exist
  only in pre-2019 vintages; they were removed from the form in
  2019-20 and beyond.
- A handful of charter / very small districts have zero SpEd
  allocation -- many items emit the `-` zero placeholder (parsed to
  NULL) rather than `0.00`.

### `fiscal_1159_staff_ratio`

Per-district per-year capture of OSPI Report 1159 "Calculation of {Year}
Certificated Instructional Staff Ratio". The form derives a single
ratio per district -- basic-education certificated instructional staff
(CIS) per 1000 K-12 students -- and checks it against the statutory
floor of 46 CIS/1000. One single-page PDF per (district, year). The
report was only published for three school years (2013-14 through
2015-16); OSPI discontinued it after the SHB 2261 / McCleary funding
rewrite of the staffing formula.

| column | meaning |
|---|---|
| `status` | `Final` (`1159(F)` -- end-of-year reconciled) or `Revised` (`1159(R)` -- intermediate snapshot, common in 2015-16 where most files were not yet finalized at scrape time). |
| `report_date_text` | Run date as printed at the top of the report (e.g. `18-Aug-16`). |
| `section` | `enrollment` (A.1-A.4) \| `cis` (B.1-B.8) \| `ratio` (C, the calculated CIS-per-1000) \| `compliance` (D Yes/No, D.1 shortfall, D.2 penalty). |
| `item_code` | Printed item id: `A.1`-`A.4`, `B.1`-`B.8`, `C`, `D`, `D.1`, `D.2`. Stable across all three vintages -- the form letters its own cross-references the same way (e.g. `[B.3 + B.4 + ((B.5 + B.6) * B.7)]` for B.8). |
| `item_label` | Item label as printed (whitespace normalized). |
| `value` | Decimal. FTE counts (A.2-A.4, B.1-B.6, B.8), the calculated ratio (C), the percentage B.7 (stored as the printed number -- `27.09` for 27.09%, not 0.2709), the shortfall (D.1), and the penalty (D.2) all share this column. NULL when the form printed no value (common on B.4 and B.6: Form SPI 1158 adjustments are rare), when the value is non-numeric (A.1's month text, D's Yes/No answer), or for the `---` placeholder used on D.2 when no penalty applies. |
| `value_text` | Raw value as printed: the month name for A.1 (e.g. `October 2015`); `Yes` or `No` for D; the literal `---` for D.2 when compliant; the formatted numeric text (with `%` suffix for B.7) for everything else; empty string when the form left the cell blank. |

**Cross-check invariants** that hold across the entire corpus:
- `C ≈ B.8 / A.4 * 1000` (within 0.05 of rounding)
- `B.8 ≈ B.3 + B.4 + (B.5 + B.6) * B.7 / 100` (within 0.01 of rounding; only holds when none of B.3/B.5/B.7 are NULL)
- When `D = 'Yes'`: `D.1` blank, `D.2 = '---'` (NULL).
- When `D = 'No'` (7 of 901 docs across the three years): `D.1` and `D.2` numeric; `D.1 = 46 - C`; `D.2 = D.1 * A.2 / 1000`.

**Coverage caveat**: 2013-14 (295 docs) and 2014-15 (299 docs) are
entirely `Final`. 2015-16 (307 docs) is entirely `Revised` -- none of
those files were re-pulled as `Final` before OSPI stopped publishing
the report. Filter on `status = 'Final'` for finalized end-of-year
analyses, or accept `Revised` to keep 2015-16 in the result.

### `fiscal_f196_unaudited_summary`

Page-2 SUMMARY block extracted from the F-196 Unaudited filing
(mid-December, pre-audit). Same 7-fund x 7-item matrix as
`fiscal_f196_summary`; consumers wanting one continuous SUMMARY series
can `UNION ALL` the two tables on `(school_year, ccddd, item_code, fund)`
(the `item_code` set is identical by design). Once the planned F-196
All Pages parser lands and back-fills 2015-16 through 2020-21, the
combined series will run 2013-14 through 2024-25.

| column | meaning |
|---|---|
| `item_code` | Positional canonical name -- same 7 codes as `fiscal_f196_summary` (`total_revenues_and_other_financing_sources`, `total_expenditures`, `other_financing_uses`, `excess_of_revenues_over_expenditures`, `beginning_total_fund_balance`, `corrections_or_restatements`, `ending_total_fund_balance`). |
| `fund` | `general`, `asb`, `debt_service`, `capital_projects`, `transportation_vehicle`, `permanent`, or `total`. `total` is the printed cross-fund sum. |
| `value` | Parsed decimal. **NULL when the form left the cell blank** -- in every file in this corpus, ASB and Permanent are blank on the `other_financing_uses` row (the audited 2021-22+ `fiscal_f196_summary` writes those as explicit 0.00 instead). The cross-fund Total invariant `total = sum(general..permanent over non-NULL)` holds for all 4,158 (file x item) rows. |

**Coverage**: 2013-14 (295 files) and 2014-15 (299 files), district-level
only. The F-196 Unaudited document was the year-end statement of record
in those two years; from 2015-16 onward OSPI shifted to publishing
'F-196 All Pages' (under `data/fiscal/fiscal/`) instead -- those are now
captured in `fiscal_f196_summary`, which also back-fills 2013-14/14-15
from the All Pages corpus (same SUMMARY content as Unaudited; both
tables overlap in those two years).

**Parser note**: Unlike `fiscal_f196_summary`, the older form leaves
non-applicable cells truly blank instead of writing 0.00. The trailing-
seven-tokens heuristic that works on the newer doc misaligns columns by
1+ on `other_financing_uses` rows. The unaudited parser uses
`extract_words()` and bins each value by right-edge x1 against the column
anchors derived from the first (always 7-column) value row.

### `fiscal_1735t_sped_enrollment`

Per-district per-age-group per-month special-education enrollment from
OSPI Report 1735T (P-223H). Single small table on the form.

| column | meaning |
|---|---|
| `grade` | Age/tier group as slug. Older years: `ages_0_2`, `ages_3_5`, `ages_k_21` (+ `age_*` variants from singular-vs-plural form drift). 2024-25: `ages_3_5`, `tier_14_18_tk`, `other_tier_tk`, `tier_1_k_21`, `other_tier_k` (last one's label wraps `-21` to a separate source line, so the slug drops the suffix). Always includes a `total` row. |
| `month` | `SEPTEMBER`-`JUNE` + `AVERAGE`. |
| `value` | Headcount as decimal (the AVERAGE column carries fractional 9-month means). |

**Scope caveat**: district-level only (same ESD-aggregate dedup
deferral as 1251).

## Joining patterns that work

```sql
-- Monthly state payment trajectory for a district / account
SELECT month, month_seq, value AS allotment_for_month
FROM fiscal_apportionment_monthly
WHERE school_year = '2024-2025' AND ccddd = 17001
  AND org_type = 'district' AND revenue_account = '3100'
ORDER BY month_seq;

-- Year-end Apportionment total per district (via TOTALS row, August)
SELECT school_year, ccddd, district, allotment_for_month
FROM fiscal_apportionment_monthly
WHERE month = 'August' AND revenue_account = 'TOTALS' AND org_type = 'district';

-- Levy authority (Schedule I.E) vs voter-approved levy (Schedule II.C) by year
SELECT auth.ccddd, auth.levy_year, auth.status,
       auth.value AS levy_authority,
       voter.value AS voter_approved
FROM fiscal_f780_levy auth
JOIN fiscal_f780_levy voter
  ON voter.school_year = auth.school_year
 AND voter.ccddd = auth.ccddd
 AND voter.levy_year = auth.levy_year
 AND voter.status = auth.status
WHERE auth.section = 'schedule_i' AND auth.item_code = 'E'
  AND voter.section = 'schedule_ii' AND voter.item_code = 'C';

-- Budget vs. actuals (F-195 Overview vs F-196 Summary), General Fund total revenues
SELECT b.school_year, b.ccddd,
       b.value AS budget_revenues,
       a.value AS actual_revenues
FROM fiscal_f195_overview b
JOIN fiscal_f196_summary a USING (class_of, ccddd)
WHERE b.section = 'a_budget_summary'
  AND b.item_code = 'total_revenues_and_other_financing_sources'
  AND b.fund = 'general'
  AND a.item_code = 'total_revenues_and_other_financing_sources'
  AND a.fund = 'general';

-- 4-year forecast trajectory for a district's General Fund expenditures
SELECT data_school_year, value
FROM fiscal_f195_four_year
WHERE school_year = '2024-2025' AND ccddd = 17001
  AND fund = 'general' AND section = 'summary' AND item_code = 'B'
ORDER BY data_year_offset;

-- F-195 Budget per-fund total expenditures vs. prior-actual:
-- the report's printed Actual / Budget / Budget triple, in one query.
SELECT fund, data_school_year, column_kind, value AS total_expenditures
FROM fiscal_f195_budget
WHERE school_year = '2024-2025' AND ccddd = 17001
  AND sub_report = 'fund_summary'
  AND section = 'summary' AND item_code = 'B'  -- 'B. TOTAL EXPENDITURES'
ORDER BY fund, data_year_offset;

-- F-195 Budget vs F-196 Actuals: prior-year actual revenue per fund,
-- comparing what the F-195 prints as Actual to the F-196 audited total.
SELECT b.fund,
       b.data_school_year AS prior_year,
       b.value AS f195_actual,
       a.value AS f196_actual
FROM fiscal_f195_budget b
JOIN fiscal_f196_summary a
  ON a.class_of = b.data_class_of AND a.ccddd = b.ccddd AND a.fund = b.fund
WHERE b.school_year = '2024-2025' AND b.ccddd = 17001
  AND b.sub_report = 'fund_summary'
  AND b.section = 'summary' AND b.item_code = 'A'  -- 'A. TOTAL REVENUES...'
  AND b.column_kind = 'actual'
  AND a.item_code = 'total_revenues_and_other_financing_sources';

-- Food Service program balance trajectory per district
SELECT school_year, ccddd, subkey AS data_year, value
FROM fiscal_food_service
WHERE section = 'carryforward' AND item_code = 'annual_balance'
ORDER BY ccddd, data_year;

-- State Institution K. TOTAL ALLOCATION (bottom line) across years
SELECT school_year, institution_name, value
FROM fiscal_state_institutions
WHERE section_code = 'K' AND section_seq = 1 AND item_path = '1'
ORDER BY institution_name, school_year;

-- 1220 SpEd: per-district total Special Education allocation per year.
SELECT school_year, ccddd, value AS total_sped_allocation
FROM fiscal_1220_sped
WHERE section = 'summary' AND item_code = 'total_allocation_spe21'
  AND status = 'Final'
ORDER BY school_year, ccddd;

-- Per-serving-district enrollment breakdown for a single (district, year):
-- "where do this district's SpEd students go to high school?"
SELECT subject_ccddd, subject_name, item_code, value
FROM fiscal_1220_sped
WHERE school_year = '2018-2019' AND ccddd = 17001
  AND section = 'serving_district_enrollment'
  AND subject_ccddd > 0
ORDER BY subject_ccddd, item_code;

-- Grants administration: total funding awarded to a district per year
-- (sum of all OPEN + CLOSED grants).
SELECT school_year, ccddd, funding AS total_funding
FROM fiscal_1191fg_grants
WHERE section = 'district_total'
ORDER BY school_year, ccddd;

-- Top grant types by funding for a single district / year.
SELECT project_code, project_description, grant_status, funding
FROM fiscal_1191fg_grants
WHERE section = 'grant_total'
  AND school_year = '2018-2019' AND ccddd = 17001
ORDER BY funding DESC;

-- Nonhigh billing: maximum payable amount from nonhigh district X to
-- high district Y in a given school year. Capture from either flavor
-- of the F-483 form and dedupe across the two POVs.
SELECT school_year, ccddd AS focal_ccddd, report_kind,
       subject_ccddd AS counterparty_ccddd, value AS payable
FROM fiscal_nonhigh_billing
WHERE section = 'payable'
  AND item_code = 'total_school_year_payable'
  AND status = 'Final'
ORDER BY school_year, focal_ccddd;

-- K-12 CIS staff ratio per district per year (the headline number C),
-- plus the compliance answer D.
SELECT c.school_year, c.ccddd, c.value AS cis_per_1000,
       d.value_text AS met_statutory_ratio
FROM fiscal_1159_staff_ratio c
JOIN fiscal_1159_staff_ratio d USING (school_year, ccddd, status)
WHERE c.section = 'ratio' AND c.item_code = 'C'
  AND d.section = 'compliance' AND d.item_code = 'D'
  AND c.status = 'Final'
ORDER BY c.school_year, c.ccddd;

-- F-196 SUMMARY series spanning unaudited (2013-14, 2014-15) and audited
-- (2021-22+) vintages -- one continuous (district, year) -> General Fund
-- total revenues trace.
SELECT 'unaudited' AS vintage, school_year, ccddd, value AS general_fund_revenues
FROM fiscal_f196_unaudited_summary
WHERE item_code = 'total_revenues_and_other_financing_sources' AND fund = 'general'
UNION ALL
SELECT 'audited' AS vintage, school_year, ccddd, value AS general_fund_revenues
FROM fiscal_f196_summary
WHERE item_code = 'total_revenues_and_other_financing_sources' AND fund = 'general'
ORDER BY ccddd, school_year;

-- Resolve source path for any row
SELECT f.*, s.source_path
FROM fiscal_f196_summary f
JOIN d_fiscal_source s ON s.source_id = f._source_id;
```

## Anti-patterns

- **Don't slug-match `item_label` across years for F-195/F-196 summary
  tables.** The label text changes (e.g. `Prior Year(s) Corrections or
  Restatements` -> `Accounting Changes and Error Corrections` in F-196).
  Use `item_code` -- it's positional and stable.
- **Don't assume Food Service exists past 2018-19** or **F-196 Summary
  exists before 2021-22**. Both have coverage gaps documented above.
- **Don't union `fiscal_f195_overview` and `fiscal_f196_summary` directly**
  -- they have different `fund` column sets (F-195 has 5 funds; F-196 has
  7 including a Permanent column and a Total column).
- **Don't filter on `revenue_account = '4156'`** and expect uniqueness
  within a year in `fiscal_state_institutions`; multiple institutions
  share the same revenue account code. Use `institution_name` to
  distinguish.
- **Don't join on `district` (the free-text name)**; it can vary between
  `Kennewick SD` and `Kennewick School District` across years and
  reports.
- **Don't use `item_label` (printed column letter) to join across years
  in `fiscal_nonhigh_billing`.** The 2019 form rewrite renumbered the
  columns (e.g. the levy in dollars moved from column A to column D;
  the May Billing moved from column H to column I). Use `item_code`
  (the semantic slug) instead. `form_variant` is provided for
  traceability only.
- **Don't use the letter A-AA cross-year for `fiscal_1220_sped`
  `account_4122` items.** The 2019-20 form re-mapped 4122 from Y/Z/AA
  to V/W/X. The parser already substitutes semantic slugs
  (`age_0_2_allocation`, `transfer_acct_4122`, `total_acct_4122`)
  for that section, so consumers should always use those slugs. For
  `account_3121`, the letter V/W/X exist in pre-2019 forms (as
  prior-year adjustments to 3121) but are absent in 2019-20+ -- expect
  NULL on missing-letter joins.
