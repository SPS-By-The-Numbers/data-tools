# STARS CSV consumer guide

This file orients a downstream reader (human or LLM) to the CSV
outputs produced by the parsers in `extractors/stars/`. The CSVs live
in `out_stars/` (gitignored; regenerated by running the `extract_*.py`
scripts plus `build_sources.py`). For schema docs, see
`extractors/stars/README.md`; for known data gaps see
`extractors/stars/COVERAGE.md`.

All of these tables are also queryable in BigQuery as
`sps-btn-data.ospi_stars.<table>` (loaded by `extractors/bqload/` via
`scripts/load_stars.sh`); the generated per-column dictionary is
`docs/DATA_DICTIONARY.md`. Row counts quoted below are snapshots from
the latest parse run.

## What the data is

OSPI publishes five report types per Washington school district per
school year as part of the **Student Transportation Allocation
Reporting System (STARS)**. The scraper at
`docs/contentscripts/scrappers/ospi-stars-reports.js` pulls every
report PDF/DOCX into `data/stars/<report_dir>/`. The parsers here
turn those source files into 8 long-form fact tables plus 7
dimension/domain tables.

| `data/stars/<dir>/` | Source files | Fact tables produced |
|---|--:|---|
| `kpi/` | 1,953 | `stars_kpi` |
| `operations_allocation/` | 2,908 | `stars_operations_allocation` + `stars_operations_allocation_compact` |
| `quarterly_district/` | 7,910 | `stars_quarterly_district` + `stars_quarterly_district_route` |
| `efficiency/` | 2,201 | `stars_efficiency` + `stars_efficiency_cohort` |
| `efficiency_review/` | 504 | `stars_efficiency_review` |

Total: **15,476 source files → 8 fact tables + 7 lookup tables**.

## Common keys used to join

Every fact table carries the `SCHOOL_YEAR_DISTRICT_FIELDS` columns
(reused from `extractors/safs/schemas/common.py`):

- `school_year` (string, e.g. `2024-2025`)
- `class_of` (int, end year of `school_year`)
- `ccddd` (int, OSPI county-and-district code)
- `county` (currently always empty; meant to be filled via a join to
  `extractors/safs/schemas/domains.py:d_ccddd`)
- `district` (district name from the filename's org-label segment)

So fact tables join to each other on `(class_of, ccddd)` and to the
SAFS budget/actuals tables on the same key.

Every fact table also carries:

- `_source_id` (int) -- FK to `d_stars_source.source_id`. Replaces the
  long filename string that previously repeated 12-35× per row.
- `_source_table` (string) -- always equals the table name; useful when
  unioning multiple tables.

## Schema landmarks (per table)

### `stars_kpi`
- `metric_code` is one of 6 codes: `basic_rider_kpi`,
  `sped_rider_kpi`, `cost_per_rider`, and each suffixed with
  `_change_pct`. The change_pct rows have `data_class_of` = the
  latest data year.
- A given report's published school year is one year ahead of the
  latest data year (e.g., 2025-2026 report dates April 2026 and
  covers data through 2024-2025).
- Three trailing data years are typically published. **2023-2024
  reports skip 2020-2021 (COVID gap)** and substitute the pre-COVID
  year, so don't assume contiguous years. `data_school_year` and
  `data_class_of` reflect the actual data year.

### `stars_operations_allocation`
- Long-form; the 30 items are catalogued in
  `d_stars_ops_allocation_item`. Use `value_kind` to know which
  numeric columns are meaningful per row.
- The "bottom line" allocation is `item_code = 'd8_actual_allocation_amount'`,
  `amount` column.
- The "formula-driven expectation" is `item_code = 'a6_calculated_expected_allocation'`.
- Joining to `d_stars_ops_allocation_section` adds the human-readable
  section title.

### `stars_operations_allocation_compact`
- Used for tribal compacts (Suquamish, Lummi, etc.) and charter
  school districts whose 1026A is structured differently:
  per-rider × prorated ridership rather than the formula-driven A-D
  sections.
- One row per district per year (not long-form). Carries both the
  host district's per-rider math (A.1-A.5) and the compact/charter's
  seasonal ridership (B.1-B.4) plus the `final_allocation`.
- `host_district` is a short name string (e.g. `North Kitsap`,
  `SPOKANE Public Schools`) -- doesn't carry the host's ccddd. To
  join it to other tables, you need a fuzzy/manual lookup. **Don't
  expect exact joins on this column.**
- `report_type` is `COMPACT` (tribal, 48 rows) or `CHARTER` (95 rows).

### `stars_quarterly_district`
- Long-form across 28 metric codes (see `d_stars_quarterly_metric`).
- `quarter` ∈ {`FALL`, `WINTER`, `SPRING`}. Most (district, year)
  tuples have all three quarters; current-year reports have only
  FALL + WINTER (SPRING is published end-of-school-year).
- `value` is `NULL` when the source's data row was *absent* (small
  districts that reported no transportation, charter ROUTE_SUMMARY
  missing route_summary_avg_stop_to_dest_distance); `value = 0` is a
  real "reported zero".
  Distinguishing these matters for ridership analyses.

### `stars_quarterly_district_route`
- One row per individual bus route in the per-quarter PDFs/DOCXs.
- `program` ∈ 6 codes (see `d_stars_route_program`). The PDF labels
  use one-letter codes (A/S/B/G/H/E); our `program` column uses
  canonical snake_case (`basic`, `special_ed`, etc.).
- `route_number` is a **string** because some districts use suffixed
  identifiers like `0079-I`, `0405-T`; small districts use bare ints
  like `1`, `7`.
- `destination_name` is free text (school names as printed). Not a
  reliable FK to anything; can be joined to `d_school` fuzzily.
- Row counts cross-check the summary table: for any (school_year,
  ccddd, quarter), `count(*) where program='basic'` should equal
  `routes_basic` from `stars_quarterly_district`.

### `stars_efficiency`
- One row per district per year (wide-ish: 10 own metrics + 2 target
  metrics + `relative_efficiency_rating`).
- `relative_efficiency_rating` is a percentage stored as a decimal
  (e.g. `74.95` means 74.95%, not 0.7495).
- For tribal compacts and charters with no transportation
  (`buses=0`, etc.), the RER is left NULL (OSPI doesn't compute one).
- `k_rte` is a poorly-documented OSPI column; almost always 0.

### `stars_efficiency_cohort`
- One row per (subject district, cohort peer) -- the peers used to
  weight the subject's target.
- `cohort_district` is the peer's short name as printed (e.g.
  `Benge`, `Mary M Knight`) -- same fuzzy-FK caveat as the
  ops_allocation_compact host_district column.
- `weight_pct` is the peer's contribution to the cohort target,
  decimal percent (e.g. `11.4` = 11.4%). Weights for a given subject
  sum to ~100%.
- Each peer's metrics are denormalized here; they also appear as the
  peer's own `stars_efficiency` row.

### `stars_efficiency_review`
- A narrative RTC report for districts whose RER crossed the 90%
  threshold or stayed below for multiple years.
- Most fields are **best-effort regex extraction** -- expect NULLs
  in the variable text fields. Reliable fields: `school_year`,
  `ccddd`, `subcategory`, `current_band`, `prior_band`,
  `current_rer`, `prior_rer`. Approximate fill rates in the current
  504-file corpus:

  | column | fill rate |
  |---|--:|
  | metadata (school_year/ccddd/bands/RER current+prior) | 100% |
  | `review_date`, `two_years_prior_rer` | 99%+ |
  | `rtc_name`, `fte_enrollment` | 95%+ |
  | `buses`, `total_cost` | 93% |
  | `basic_ride_equivalents`, `special_ride_equivalents` | 74% |
  | `rtc_esd` | 13% (only the older "from <ESD>" phrasing carries it) |

- `subcategory` is the OSPI band-crossing label; we also decode it
  into `current_band` / `prior_band` (each `above_90` or `below_90`).

### `d_stars_source`
- Bridge dimension. Every fact-table row has `_source_id` pointing
  here. Carries pre-parsed `school_year`, `class_of`, `ccddd`,
  `district`, `subcategory`, `original_name`, `extension`, plus
  `report_dir` (which `data/stars/` subdir the file came from).
- `source_id` is sequential in sorted-filename order; stable across
  reruns as long as the set of source files is stable.

## NULL conventions

- `value = NULL` in `stars_quarterly_district` ⇒ the source PDF/DOCX
  didn't print that section's data row at all (small/zero-activity
  districts, charters missing route_summary_avg_stop_to_dest_distance).
  `value = 0` ⇒ OSPI
  printed a literal zero (e.g. COVID-era zero ridership).
- `relative_efficiency_rating = NULL` in `stars_efficiency` ⇒ OSPI
  didn't compute one (districts with no transportation).
- `county` column is always blank in fact tables; populate via a
  join to `extractors/safs/schemas/domains.py:d_ccddd` if needed.
- `cohort_district` / `host_district` columns carry free-text
  district names; NULL is rare but means the parser couldn't extract
  them from the source.
- `rtc_name`, `rtc_esd`, `fte_enrollment`, etc. in
  `stars_efficiency_review` may be NULL when the narrative phrased
  things in a way the regex didn't match -- not a parser error.

## Known data gaps

See `COVERAGE.md` for full detail. Headline gaps:

- **No `efficiency`, `kpi`, `operations_allocation`, or
  `quarterly_district` for 2016-2017.** STARS as a reporting program
  launched 2017-2018; the 2016-17 `efficiency_review` files are a
  retrospective comparison artifact.
- **No `efficiency` or `kpi` for 2020-2021 or 2021-2022.** COVID
  transit shutdown -- buses didn't run, so efficiency/KPI metrics
  weren't computed. `operations_allocation` and `quarterly_district`
  do exist for these years.
- **Winlock 2025-2026 KPI** is a 4-page truncated PDF (cover + 4
  cohort tables but no per-district KPI block). OSPI's dropdown
  confirms they didn't publish a full version. `stars_kpi` has 0
  rows for (`ccddd=21232`, `school_year='2025-2026'`).
- **129 (district, year) pairs in 2018-2019 `quarterly_district`
  have only FALL + WINTER** (no SPRING). Worth verifying against
  OSPI before treating these as bug-free.

## Joining patterns that work

```sql
-- Translate KPI metric codes into descriptions
SELECT k.school_year, k.district, k.value, m.description, m.unit
FROM stars_kpi k
JOIN d_stars_kpi_metric m USING (metric_code)
WHERE m.is_change_pct = false
  AND m.base_metric = 'basic_rider_kpi';

-- Resolve the source filename for any row
SELECT k.*, s.source_filename, s.report_dir
FROM stars_kpi k
JOIN d_stars_source s ON s.source_id = k._source_id;

-- Cross-table join: route counts vs basic ride-equivalents for a quarter
SELECT q.ccddd, q.school_year, q.quarter,
       MAX(CASE WHEN q.metric_code='basic_program_total' THEN q.value END) AS basic_ride_equivalents,
       MAX(CASE WHEN q.metric_code='routes_basic' THEN q.value END) AS basic_routes
FROM stars_quarterly_district q
GROUP BY 1,2,3;

-- Join to SAFS budget/actuals on (class_of, ccddd)
SELECT e.school_year, e.district, e.relative_efficiency_rating,
       a.amount AS total_actuals
FROM stars_efficiency e
JOIN actuals_general_fund_expenditures a USING (class_of, ccddd);
```

## Anti-patterns

- Don't join on `host_district`, `cohort_district`, or
  `destination_name` as if they were canonical FKs -- they're
  free-text district/school names printed in the PDFs. They mostly
  match the canonical `district` field in `d_ccddd`/`d_school` but
  not always (e.g. `Mary M Knight` vs `Mary M. Knight`).
- Don't assume the three KPI data years are contiguous; the 2023-24
  reports skip 2020-21 because of the COVID gap.
- Don't interpret `value = NULL` and `value = 0` interchangeably in
  `stars_quarterly_district`; they mean different things (see NULL
  conventions above).
- Don't union `stars_operations_allocation` and
  `stars_operations_allocation_compact` directly -- they have
  different schemas (long-form vs wide one-row-per-district).
- Don't treat `stars_efficiency_review.basic_ride_equivalents` /
  `special_ride_equivalents` as a complete column -- they have a ~74%
  fill rate because of narrative phrasing variations.
