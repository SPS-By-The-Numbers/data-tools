Content scripts

Browser console scripts for scraping public data portals. Open the target page, open DevTools (⌥⌘I), and either paste the full script (Copy script) or paste the loader one-liner, which fetch()es and runs the script without copying the whole body.

Configuration & tips

Bound the run with START / END

Both OSPI scrapers walk a cascade of dropdowns. You can bracket the run with window.OSPI_SCRAPER_START and window.OSPI_SCRAPER_END, set before pasting the loader. Keys are the cascade level's box id; values can be either the option's value (string) or its visible label.

// STARS: resume at year 2023, report type 14, org Aberdeen
window.OSPI_SCRAPER_START = { years: '2023', report_types: '14', orgs: '3247' };
fetch("contentscripts/scrappers/ospi-stars-reports.js").then(r=>r.text()).then(eval);

// Single year, single report type: just one combination's slice of orgs
window.OSPI_SCRAPER_START = { years: '2023', report_types: '14' };
window.OSPI_SCRAPER_END   = { years: '2023', report_types: '14' };
fetch("contentscripts/scrappers/ospi-stars-reports.js").then(r=>r.text()).then(eval);

// SAFS: every report type in 2024-2025, stop after Operations Allocation Detail
window.OSPI_SCRAPER_START = { years: '2024' };
window.OSPI_SCRAPER_END   = { years: '2024', report_types: 'Operations Allocation Detail' };
fetch("contentscripts/scrappers/ospi-funding-reports.js").then(r=>r.text()).then(eval);
  • Both bounds are CLOSED intervals (inclusive on both ends). A run with START=(2023,14,3247) and END=(2024,14,3247) processes 3247 under 2023+14, everything in 2023+14 after 3247, all of 2023+other report types, all of 2024 up to and including 3247 under 14, and stops.
  • Iteration order is the page's own option order (not chronological or alphabetical — whatever the dropdown lists). On the STARS page years are listed newest first, so e.g. START=2023 means "skip 2025 and 2024, start at 2023". When in doubt, look at the dropdown order in the page.
  • Lower-priority keys can be omitted. { years: '2023' } as START resumes at 2023 and iterates every report type / org below it. { years: '2023' } as END means "stop after finishing everything under 2023".
  • Labels work too. { years: '2023-2024' } is equivalent to { years: '2023' }.
  • Filters lift past the matched boundary. Once the cascade steps past the START match at a given level, the START filter is dropped for deeper levels. Same for END. So START={years:'2023',orgs:'3247'} means "in 2023, skip orgs before 3247; in 2024+ years, iterate all orgs from the top."
  • If a bound's value isn't found in the current options, the scraper logs [resume] … not found and skips that branch. Usually means a typo in the value.
  • Read the last good console log line to find the value/label pair you want to bound at — log lines look like orgs: Aberdeen School District(14005) (3247).

Pre-run setup (Chrome)

  • Settings → Downloads → "Ask where to save each file": turn this off and pick a target directory, or every PDF will show its own save-as dialog.
  • "Allow multiple downloads": the first time the scraper kicks off more than one file from the site, Chrome shows a prompt — click Allow.
  • Downloads are pulled via fetch + Blob, so files always save (never open in the PDF viewer).

Pacing & concurrency

Defaults baked into both scrapers:

  • Jitter between download starts: uniform random in [DOWNLOAD_GAP_MIN_MS, DOWNLOAD_GAP_MAX_MS] (currently 100 ms – 750 ms).
  • Max concurrent downloads: MAX_CONCURRENT_DOWNLOADS = 4 across all combinations.
  • Per-combination AJAX waits use the page's own $(document).ajaxSend / ajaxComplete hooks, with a 600 ms idle threshold.

To override, edit the constants near the top of each script before pasting (use Copy script, edit in the console, then run).

Logs to watch

  • [start] <file> (N inflight, next in Xms) — fetch dispatched, N currently in flight, next start scheduled in X ms.
  • [ok] <file> — fetch completed and the browser was prompted to save it.
  • [fail] <url> (<file>) — fetch errored. Hover/expand for the exception.
  • [skip] <prefix> - no documents — this combination had an empty #documents div after AJAX settled.
  • [resume] <boxId>: skipped N option(s), starting at … — confirms the START filter took effect.
  • [range] <boxId>: reached end at … — confirms the END filter took effect and iteration at that level stopped.

Troubleshooting

  • Nothing happens / no network activity. Run the STARS diagnostic (below) and paste its output. Most likely the dropdowns aren't where the scraper expects them.
  • [fail] … Failed to fetch in bulk. Usually a CORS or network issue. The scraper already sets credentials: 'omit' for the document host; if you see this on a different host, that host may have stricter CORS.
  • Files open in Preview instead of saving. The scraper forces application/octet-stream on download. If your OS is still opening files after save, that's a per-OS "open with default app" setting, not the scraper.
